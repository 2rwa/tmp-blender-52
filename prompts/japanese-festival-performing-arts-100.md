# 祭礼・芸能100種 — 公開用・再生成プロンプト

> **用途**：日本の祭礼・伝統芸能を題材にした3Dテストモデル100種を、Blender 5.2で生成・検証・公開するための再利用可能な指示書。
>
> **位置づけ**：このプロンプトは現行の公開ソースコードと成果物から再構成したものです。非公開のチャット記録や内部指示を転記したものではありません。

---

## 制作依頼（以下をAIや開発者への指示として使用）

このリポジトリを出発点として、日本の祭礼・芸能に関する **精密ローポリ3Dモデルを100種類**、Blender 5.2で作成・検証・公開してください。単なる仕様提案や雛形だけで終わらず、利用可能な書き込み権限があれば実装・コミット・GitHub Actions実行・検証・ギャラリー公開まで行ってください。

**品質は処理の軽さより優先**します。神輿、山車、曳山、鉾、櫓のような構造物も作成し、モデル数を揃えるためだけの単純な箱や球に置換しないでください。

### 2. モデルの種類と品質

- 10カテゴリ×10種＝計100種。カテゴリは matsuri（神輿・山車・鉾など）、ritual（祭礼道具）、shinji（神事）、gakki（和楽器）、noh（能・狂言）、kabuki（歌舞伎）、buyo_folk（舞踊・民俗芸能）、costume（装束）、stage（舞台設備）、local（郷土芸能）。
- 各作品に固有の造形と、明確に識別できるシルエットを与える。同じ汎用モデルの色・名前を変えただけの作品で数を合わせない。
- 実際の構造を別メッシュで作り、部品を意味の分かる英語名で命名する。
- 神輿・山車：屋根、棟、鳳凰や装飾、欄干、担ぎ棒、台枠、金具、提灯、房。車輪は該当する題材のみに付ける。
- 面：額、眼窩、頬、鼻、口、顎、耳、角、牙など、題材ごとに異なる凹凸と彩色。
- 楽器：胴、張皮、鋲、紐、木目、台座、バチ、笛の孔、金具等を個別に表現。
- 装束：袖、襟、帯、紐、結び、ひだ、房、織柄を実ジオメトリで表す。
- 舞台：柱、梁、床、幕、階層、骨組み、継手、装飾部品を分離。
- 単なるポリゴン細分化ではなく、形状・構造の再現性と見栄えを優先する。大物に不自然な一律のポリゴン上限を設けない。
- 実験用の様式化は許容する。ただし、実際の地域・祭礼・芸能の歴史的な忠実性を無検証で保証しない。

### 3. 生成器の構成

- 生成コードは experiments/japanese-festival-performing-arts-100/ の中に置く。
- 共通形状関数は geometry.py と parts.py にまとめる。
- カテゴリ固有の造形は model_<category>.py に置き、カテゴリ内の10題材を make(variant) で生成する。
- scene.py は100種のカタログを参照し、1回につき1カテゴリ10品目を処理する。
- 外部の非公開リポジトリ、特定個人の作業端末、ローカルの絶対パスには依存しない。
- 実験として作成可能なオリジナルの手続き的メッシュを使用する。第三者の商用3Dモデルや画像を無断で同梱しない。

### 4. Blenderと出力仕様

- Blender **5.2.2**、Python bpy、Workbenchレンダー。
- マテリアル色、スタジオ照明、影、キャビティを設定。
- **500×400ピクセル、24fps、144フレーム（6秒）**のターンテーブルを出力。
- 被写体を中心に正規化し、正面、斜め、背面が分かる回転カメラを使用する。
- 細長い笛や棒などは、端面だけのプレビューを選ばない。
- 各品目ごとに **.blend / .glb / preview.png / turntable.mp4 / metadata.json** を生成。
- metadata.json にID、日本語名、カテゴリ、生成器バージョン、Blenderバージョン、面数、メッシュ部品数、素材数、解像度、フレーム数、採用プレビューフレームを記録。
- 一時出力は output52/items/<id>/、検証済みの永続保存先は results/japanese-festival-performing-arts-100/items/<id>/。
- Pagesギャラリーは docs/festival-performing-arts/ に生成。検索、カテゴリ絞り込み、プレビュー、回転動画、3Dデータへのリンクを表示。公開ホスト名は現在のリポジトリに合わせる。

### 5. GitHub Actionsと検証

1. Blenderの実行前に Python のコンパイル検査、カタログ100件とID重複検査、回帰テストを行う。
2. 専用のGitHub Actionsで **10カテゴリを10並列**で生成する。現行のレンダージョブは180分上限。
3. 生成後に .blend / .glb の実体と形式、PNGの解像度、MP4の144フレーム、面数、部品数、素材、プレビューの明暗差・可視領域を検証する。
4. **細長いモデル**には縦横とも同じ最小ピクセル数を強制せず、長辺・短辺・可視画素数などで判定する。
5. 画像のコントラスト不足や面数不足で失敗した場合、まず **モデルの形状・金具・配色・姿勢・撮影アングル**を修正し、基準を安易に緩めない。
6. 実際のActionsログから失敗原因を特定し、必要な回帰テストを追加して再実行する。
7. 全100種合格後に results/ へ保存して、ギャラリー生成とPagesデプロイまで成功を確認する。
8. 実行中、キュー待ち、未公開の状態を「完成」と報告しない。記録したログや出力だけでなく、可能な範囲で画像の見た目もチェックする。

過去の改善例：龍笛は暗い横長形状のコントラストを明るい巻糸や金具で補う。歌舞伎の煙管は彫金・接続金具など小物の細部まで作る。田楽鍬は木地・縁飾りなどの視認性を改善する。
